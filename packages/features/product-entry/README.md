## ساختار

```text
src/
├─ domain/entry-draft.ts                  مراحل جادوگر، واحدها و تبدیل، بهای هر واحد پایه، toRegisterRequest
├─ application/ports.ts                   EntryCatalog، EntryCommands، EntryDrafts
├─ infrastructure/http-entry-api.ts       یک متد برای هر endpoint + نگاشت DTO
├─ infrastructure/entry-draft-repository.ts  پیش‌نویس در DraftStore (کلید فروشگاه + کاربر)
└─ ui/
   ├─ common/                            نشست پیش‌نویس، ناوبری، شروع جریان، پوسته‌ها و نمایش مشترک
   ├─ identification/                    روش ورود، بارکد، جستجو، انتخاب و اصلاح شناسایی
   ├─ details/                           مشخصات، ویژگی‌ها، تصویر و ایجاد درجا
   ├─ units/                             ویرایش واحد و بسته
   ├─ stock/                             منشأ و موجودی اولیه
   ├─ pricing/                           قیمت‌گذاری و پیش‌نمایش
   ├─ bulk/                              ثبت گروهی
   ├─ attachments/                       اتصال کالاهای کاتالوگ به فروشگاه
   ├─ review/                            مرور و نتیجهٔ ثبت
   ├─ i18n/                              کاتالوگ ترجمه و اتصال به مترجم
   └─ tests/                             تست‌های ترکیبی چند بخش
```

داخل هر بخش فقط دسته‌های لازم ساخته می‌شوند: `screens/components/hooks/state/presentation/types/constants/schemas/tests`.
فایل همراه در دستهٔ خودش می‌ماند؛ داخل components فقط کامپوننت و داخل hooks فقط هوک قرار دارد.
بخش به بخش دیگر import مستقیم ندارد؛ اجزای مشترک در common و ترکیب واقعی چند بخش در `ui/screens` قرار می‌گیرند (فعلاً چنین صفحه‌ای نداریم).
قرارداد Save در `common/types/use-entry-draft.types.ts` و مالک آن در `common/hooks/use-entry-draft.ts` است.
API عمومی `src/index.ts` ثابت است. سیاست اجرا در `tools/architecture/ui-organization.mjs` ثبت شده و checker همان ابزار معماری مخزن است.

## الگوی نمایش، ستون‌ها و رندر — 2026-10-20

مبنای این feature، [الگوی قابل‌توسعهٔ گرید](../../../docs/architecture/grid-columns.md) است. فقط `AttachmentRecords` و `AttachmentSummary` مصرف‌کنندهٔ `DataGrid` هستند؛ فرم یا فهرست دیگری صرفاً برای یکسان‌شدن ساختار به گرید تبدیل نمی‌شود. React Compiler غیرفعال است و memoization لازم حفظ می‌شود.

| بخش                                        | تصمیم و دلیل                                                                                                                                                                                                                                                                    |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `attachments`                              | metadata ستون‌ها در constants، اتصال داده و ترجمه در hookهای ویژگی و ساخت ستون‌ها با `useGridColumns`. اشتراک انتخاب هر ردیف در سلول همان ویژگی می‌ماند.                                                                                                                        |
| `bulk`                                     | ستون‌های تایپ‌شده در `bulk-row-columns.constants.ts`؛ نمایش سلول و کارت در `BulkRowCell` و `BulkRowCard`. callbackهای ویرایش پایدارند. `RecordList` استثنای عمدی است: همهٔ ردیف‌های رسید در دسکتاپ و ویرایش کارت موبایل داخل Overlay حفظ می‌شوند؛ صفحه‌بندی جدید اضافه نمی‌شود. |
| `identification`                           | گزینه‌های ثابت اصلاح مشخصات در constants. `SearchResults` دو فهرست cursor مستقل و autocomplete دارد؛ همین رفتار باقی می‌ماند و به DataGrid تبدیل نمی‌شود.                                                                                                                       |
| `review`                                   | ستون‌های نتیجهٔ مستقل و نگاشت وضعیت بها در constants. `StandaloneResult` خلاصهٔ یک ثبت است و همان `RecordList` تک‌ردیفی می‌ماند.                                                                                                                                                |
| `units`                                    | ویرایش بسته در `UnitPackRow` جداست؛ callbackهای ثابت و حفظ مرجع ردیف‌های بدون تغییر، ویرایش را موضعی نگه می‌دارند. اعتبارسنجی، autosave، حذف، ترتیب و گذار مرحله در `UnitsForm` حفظ شده‌اند.                                                                                    |
| `pricing`                                  | گزینه‌های ثابت روش قیمت و جهت گردکردن در constants؛ گزینه‌های قراردادی از مقادیر تولیدشده مصرف می‌شوند. اشتراک قیمت زنده همچنان در برگ‌های فرم است.                                                                                                                             |
| `details`                                  | فیلدهای ثابت برش تصویر در constants؛ URL پیش‌نمایش با اتصال ref ساخته و با cleanup همان ref آزاد می‌شود. ساخت منبع مرورگر به `useMemo` وابسته نیست. فرم جزئیات و autosave موجود حفظ می‌شوند.                                                                                    |
| `stock` و `common`                         | فرم موجودی، پیش‌نمایش تبدیل، نشست و ذخیرهٔ پیش‌نویس از قبل مسئولیت‌های جدا دارند. داده‌های پویا و گزینه‌های کوتاه، wrapper یا memo تازه نمی‌گیرند. `useEntryPresentation` مصرف حساس به هویت تابع ندارد.                                                                         |
| `domain`، `application` و `infrastructure` | قواعد تجاری، محاسبات Decimal، قرارداد API، ذخیره و idempotency مستقل از الگوی نمایش‌اند؛ تغییر نکرده‌اند.                                                                                                                                                                       |

این جدول نتیجهٔ بررسی کل feature است، نه الزام به تغییر همهٔ فایل‌ها. برای توسعهٔ بعدی، metadata و رفتار در مالک خود بمانند؛ اگر لایهٔ تازه سود مشخصی ندارد، شکل ساده‌تر با یک دلیل کوتاه کافی است.

تست‌های `BulkRows` و `UnitsForm` ویرایش، فوکوس، داده و callback تازه و فراخوانی فیلد ردیف نامرتبط را بررسی می‌کنند. `ImageEditor` برای تعویض فایل، StrictMode و آزادسازی URL آزمون دارد. این شواهد دربارهٔ رفتار و دامنهٔ رندرند؛ بنچمارک زمان پاسخ‌گویی، حافظه یا مقایسهٔ پیکسلی قبل/بعد محسوب نمی‌شوند.

### اعتبارسنجی این بازبینی

- `corepack pnpm --filter @dukani/product-entry test`: هر ۱۳۱ آزمون در ۳۲ فایل موفق، شامل ۱۳ آزمون جدید برای bulk، units و تصویر.
- typecheck و lint بسته موفق. lint هشدار شناخته‌شدهٔ نبود cache گراف Nx دارد؛ بررسی مستقل معماری روی ۱۶۲۲ فایل و بررسی ترجمه بدون مشکل انجام شدند.
- اسکریپت‌های مرورگر زیر با Chrome و `NEXT_PUBLIC_API_MODE=mock` در عرض‌های ۳۹۰ و ۱۴۴۰ موفق بودند؛ تصاویر ردیف‌های ثبت گروهی، بسته‌ها و قیمت نیز بازبینی شدند:
  - `tools/scripts/flow-entry.mjs`: جست‌وجو، رد مجوز دوربین، اعتبارسنجی بارکد و ثبت کامل رسید گروهی؛ تصاویر در `front/tmp/entry-qa/`.
  - `tools/scripts/flow-entry-details.mjs`: حفظ ورودی جزئیات، صحنهٔ ویژگی و ساخت درجای برند با refresh و Back، و حفظ ورودی موجودی و قیمت؛ تصاویر در `front/tmp/f10-details-qa/`.
  - `tools/scripts/flow-f12.mjs tmp/product-entry-refactor-f12`: واحد و کاربرد خرید/فروش، بایگانی واحد، بستهٔ کالای تازه، تبدیل موجودی و حفظ قیمت مستقل بسته؛ تصاویر در مسیر خروجی مشخص‌شده. انتظار مسیر قدیمی خرید در اسکریپت با مسیر جاری `purchases/continuous` هماهنگ شد.

پوشش مرورگر به همین سناریوهای آزمایشی محدود است؛ build تولید و API واقعی در این مرحله ارزیابی نشده‌اند. فهرست تصمیم‌ها و موارد حفظ‌شدهٔ بالا مبنای ادامهٔ توسعه است.

## نکته‌ها

- پیش‌نویس هر مرحله با کلید `storeId:userId:product-entry:draftId` ذخیره می‌شود؛ refresh یا بستن مرورگر ورود را از دست نمی‌دهد و کاربر دیگر آن را نمی‌بیند.
- مقدار و پول Decimal string است؛ «بها نامعلوم» صفر نیست (`costStatus: Unknown`).
- تاریخ تولید بعد از انقضا یا در آینده پذیرفته نمی‌شود (`StockForm.schema.ts`، تست دارد).
- ثبت نهایی idempotent است و پاسخ گم‌شده را با همان شناسهٔ عملیات بررسی می‌کند.
