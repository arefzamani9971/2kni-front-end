# چندزبانگی

زبان پیش‌فرض `fa` و زبان دوم `en` است. کتابخانهٔ next-intl فقط در `@dukani/i18n` مصرف می‌شود؛ اپ‌ها، ui-kit و UI فیچرها از Facade آن استفاده می‌کنند. Domain/Application به ترجمه وابسته نیستند و کد خطا یا دادهٔ خام می‌دهند.

مالک پیام، مالک کاتالوگ است؛ `shared/i18n` فقط اتصال کتابخانه، provider، locale، جهت و قالب‌بندی مشترک را نگه می‌دارد و به اپ یا فیچر وابسته نیست.

| مالک        | محل کاتالوگ fa/en                | مسئولیت                                       |
| ----------- | -------------------------------- | --------------------------------------------- |
| کنترل عمومی | `shared/ui-kit/src/i18n`         | عنوان، placeholder، دسترس‌پذیری و خطای کنترل  |
| فرم         | `shared/forms/src/i18n`          | پیام قواعد اعتبارسنجی مشترک                   |
| UI فیچر     | `features/<feature>/src/ui/i18n` | کپی و presentation همان فیچر                  |
| اپ          | `apps/<app>/src/i18n`            | پوسته، ناوبری، metadata و request composition |

UI از hook محلی مبتنی بر `useCatalogTranslations(catalogs)` و کد خالص از `createCatalogTranslator(locale, catalogs)` استفاده می‌کند. کلیدها با کاتالوگ مالک type-check می‌شوند. کاتالوگ پایهٔ provider فعلاً خالی است؛ پیام فیچرها در shared جمع نمی‌شود. هر مالک دو کاتالوگ خود را import می‌کند؛ بارگذاری تنبل فقط با نیاز واقعی اندازهٔ bundle اضافه شود.

کلیدها معنایی‌اند؛ جملهٔ کامل با ICU و پارامتر/جمع ترجمه می‌شود. برچسب enumها در presentation فیچر نگاشت می‌شود. نام محصول، واحد و سایر داده‌های کاربر/API ترجمهٔ خودکار نمی‌شوند. ترجمهٔ خطای سرور نیازمند قرارداد code است و detail ناشناخته fallback باقی می‌ماند.

`useFormatter` و `useLocale` برای UI؛ مسیر `@dukani/i18n/server` برای provider سرور و request config؛ hook کاتالوگ محلی در Server Component همگام نیز قابل مصرف است. در سرور locale mutable سراسری نداریم. منطقهٔ زمانی `Asia/Tehran` صریح است. state و کش باید دادهٔ خام یا کد خطا نگه دارند؛ ترجمه در render انجام شود. Domain فقط code/reason خطا می‌دهد؛ forms با `createRules(t)` و `useValidationRules()` پیام را می‌سازد و قواعد به factory schema تزریق می‌شوند. `rules` پیش‌فرض فارسی برای سازگاری مصرف‌کننده‌های قدیمی باقی است.

فرم UI از `useLocalizedAppForm` استفاده می‌کند؛ این adapter با تغییر locale فقط فیلدهای دارای خطای schema را دوباره اعتبارسنجی می‌کند. مقدار، dirty state و خطاهای manual/server حفظ می‌شوند. `useAppForm` عمومی به provider زبان وابسته نیست و `validationKey` اختیاری برای تغییر context اعتبارسنجی دارد. پیام سرور یا خطای دستی بدون code قابل ترجمهٔ خودکار نیست.

اپ‌ها request config مستقل دارند و از plugin مشترک استفاده می‌کنند. در این مرحله locale تولید فارسی ثابت است؛ مسیرها و خروجی استاتیک landing حفظ می‌شوند. زبان انگلیسی در provider و نوار Language در Storybook قابل آزمون است. فعال‌سازی تغییر زبان عمومی و routing/SEO انگلیسی پس از مهاجرت متن‌های فیچرها انجام شود؛ انگلیسی فعلی کل محصول ترجمه‌شده محسوب نمی‌شود.

جهت با `getDirection(locale)` تعیین می‌شود؛ Portalها و کنترل‌های Radix از همان locale استفاده می‌کنند. ورودی شماره، کد و تاریخ تایپی LTR می‌ماند. تقویم Jalali فعلی یک کنترل صریح شمسی است؛ انگلیسی نام ماه/روز و ارقام را تغییر می‌دهد و آن را Gregorian نمی‌کند. مقدار API همچنان Gregorian DateOnly است. `formatDecimalString` با BigInt و ارقام جزء اعشار قالب‌بندی می‌کند؛ مبلغ Decimal نباید به Number تبدیل شود.

تست کامپوننت‌های مصرف‌کننده provider واقعی دارند (`@dukani/i18n/testing`). Storybook دو زبان را با provider واقعی نشان می‌دهد. تست کاتالوگ، plural، جهت و حفظ وضعیت هنگام تغییر زبان باید کنار رگرسیون UI اجرا شود.

`pnpm i18n:check` برابری کلیدهای fa/en و نبود کپی فارسی مستقیم در کد production اپ‌ها، UI فیچرها، ui-kit و forms را کنترل می‌کند و در lint/check اجرا می‌شود. کامنت، تست، Storybook، الگوی رقم و دادهٔ API موضوع این gate نیستند؛ عبور از آن تأیید ترجمهٔ همهٔ پیام‌های سرور یا صحت بصری کامل LTR محسوب نمی‌شود.
